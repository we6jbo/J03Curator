# Screenshot publication policy (v0.2)

- At most one **published** screenshot per project. Prefer the latest eligible image captured near completion.
- `J03Curator screenshot NAME` scans `~/.38bTqEvQc/NAME/` for PNGs and reports the latest as a candidate.
- `J03Curator screenshot NAME --select-latest` records one *unapproved* candidate in `screenshot_choices`. No files are copied, committed, pushed, or published.
- Manual privacy analysis, copyright verification, and screenshotpublisher approval must occur **before** publication.
- Existing screenshots and historical captures are never deleted.
- If an image changes, prior hash approval must not carry over.
- Publish one representative image for both GitHub and the WordPress article, not an entire capture gallery.
- The project registry continues to allow multiple appropriate source-code files and supporting materials.
- Do not publish a project when copyright is Yes or usefulness is No.
- Future publisher integration must enforce this rule on both GitHub and Imgur independently, and verify remote result.
